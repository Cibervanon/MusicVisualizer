Visión General

Lumen Studio es un estudio local de creación de videoclips musicales sincronizados, desarrollado como aplicación 100% local sin dependencias en la nube, APIs pagas ni servicios externos. Todo el procesamiento ocurre en tu máquina.

🎯 Objetivo: Permitir a músicos y creadores generar videoclips profesionales sincronizados con su música, con calidad comparable a estudios profesionales, pero sin costos de nube ni límites de uso.

Principios de Diseño

  • Local-first: Zero cloud dependencies. Todo corre en tu hardware.
  • Privacidad total: Tu música y video nunca salen de tu máquina.
  • Calidad profesional: Render H.264 + AAC, validado con ffprobe, normalizado a −14 LUFS.
  • Extensible: Arquitectura modular para añadir estilos, efectos, analizadores.
  • Accesible: UI en español, dark mode premium, navegación por teclado, ARIA completo.

    🎵 Análisis Musical Inteligente

    Detección de BPM, beats, downbeats, secciones (intro/verse/chorus/drop), eventos musicales (energy up/down, silence, kicks) y envolventes espectrales por banda (kick, bass, snare, hat).

    🎬 Análisis Visual Avanzado

    Detección de escenas con PySceneDetect, medición de movimiento óptico, calidad, nitidez, brillo. Biblioteca de escenas reutilizable.

    ✂️ Planificación de EDL Sincronizada

    10 estilos de montaje (Cinematic, Dynamic, Beat Sync, Fast Cuts, Smooth, Emotional, Flash, Modern, Minimal, Experimental). Cortes anclados a beats/downbeats con diversidad de escenas.

    🎨 Render con Efectos Profesionales

    Grade (contraste/saturación/brillo), efectos (sharpen, vignette, grain, glow, RGB split), transiciones (cut, crossfade, flash), burn-in de subtítulos con libass.

    🎤 Sistema de Letras Animadas

    Editor visual con drag-and-drop, importación SRT/LRC/texto plano, transcripción Whisper (faster-whisper), animaciones de entrada/salida, preview en tiempo real.

    ⚡ Pipeline Asíncrono Robusto

    Jobs asíncronos con progreso real (FFmpeg progress), cancelación segura, reintentos, validación automática con ffprobe (duración, resolución, fps, codecs, sync A/V, keyframes, perfil H.264).

Funcionalidades Principales

🎵 Análisis Musical (app/analysis/audio_analyzer.py)

Basado en librosa con fallback robusto. Todo calculado offline, sin APIs externas.

  • BPM & Tempo: librosa.beat.beat_track → BPM, confidence, med/MAD de intervalos. Fallback a grid honesto si falla.Beats & Downbeats: Ventanas de 5 frames alrededor de cada beat → strength vectorial normalizada (percentil 99) → downbeats por fase 4/4 que maximiza suma de acentos. Confianza de downbeat = separación entre mejor/segunda fase × soporte (mín 8 beats).
  • Envolventes Espectrales: STFT → 4 bandas (kick/bass/snare/hat) + RMS + spectral flux. Normalización percentil 98.
  • Secciones: Agglomerative clustering espectral (2-9 segmentos) → labels heurísticos (intro/verse/chorus/drop/build/breakdown/outro) por intensidad/flux.
  • Eventos Musicales: energy_up/down, drop, section_change, silence, strong_beat, kick - todos anclados a tiempo real con strength.

    🎬 Análisis Visual (app/analysis/video_analyzer.py)

    Basado en PySceneDetect (ContentDetector) + OpenCV para métricas por escena.

  • Detección de Escenas: ContentDetector threshold adaptativo → lista de escenas con start/end frame/time.
  • Métricas por Escena: Motion (optical flow Farneback), Quality (sharpness Laplaciano), Brightness, Stability, Colorfulness, Saliency center, Tags (static/motion/high_quality/low_quality).
  • Master Normalizado: Un solo archivo master por proyecto (scale/crop/fps/format fijos). Cacheado por hash de fuente + params. Reutilizable para todos los clips.Thumbnail: Frame representativo (35% duración) escalado a 720px ancho.

    • ✂️ Planificación EDL (app/editing/planner.py + generator.py)

    El planificador es el cerebro creativo: convierte beats + escenas + estilo → EDL (Edit Decision List) ejecutable.

  • Grid de Cortes: Beats + mid-beats + section boundaries + event times → candidatos válidos.
  • Duración Objetivo por Estilo: Cada estilo define beat_min/beat_max, min_shot/max_shot, transition (cut/crossfade/flash).
  • Scoring Multi-criterio: Fit (duración vs objetivo), Beat alignment (distancia a beat/downbeat), Event bonus, Section bonus, Phrase bonus (cada 8 beats), Scene quality, Motion match, Diversity (penaliza reuso), Jitter aleatorio.Selección de Escena: Weighted random con pesos configurables (scene/quality/motion/diversity/energy) + bias a inicio de escena configurable.
  • Validación EDL: Duración suma = EDL duration, source_duration ≥ duration, bounds check (scene bounds + master duration), unique segment IDs, min duration 0.12s.Diversidad: used_counts penaliza reuso de escenas. version_index + seed determinista → variaciones controladas.

    🎨 Render Pipeline (app/media/render.py)

    Un solo comando FFmpeg por clip. Construye filter graph complejo → un solo proceso FFmpeg → máximo rendimiento.

  • Inputs: Un -i master por segmento (con -ss/-t para seek rápido) + 1 -i audio.
  • Filters por Segmento: trim exacto (duration del segmento, no source_duration), setpts, fps, scale (lanczos), setsar=1, settb=AVTB. Flash: fade in/out white en transiciones.
  • Concat vs Xfade: concat para cuts (inputs trimeados exactos). xfade=fade para crossfade con offset calculado. Flash: fade white en cortes.
  • Duración Exacta: tpad=stop_mode=clone:stop_duration=1 + trim=duration=EDL_duration → garantía frame-perfect.Efectos (filter chain): eq (grade), unsharp (sharpen), vignette, noise (grain), gblur+blend=screen (glow), rgbashift (RGB split). Solo si permitidos por estilo.
  • Subtítulos: libass → ass_filter() → quemado en video.
  • Audio: atrim + asetpts + volume + loudnorm=I=-14:TP=-1.5:LRA=11 (estándar streaming).
  • Encoding: H.264 High Profile (libx264 / h264_qsv), CRF configurable, -movflags +faststart, -shortest para sync garantizado.Validación Post-Render: ffprobe completo → duration ±1 frame, resolution, fps, codecs, has_audio/has_video, size > 20KB, full decode test (-f null -), A/V sync (PTS drift), keyframe interval, H.264 profile/level, color space.

    • 🎤 Sistema de Letras (app/lyrics/)

    • Editor Visual: Tabla virtualizada (react-window), drag-to-reorder (react-dnd), inline editing, per-line preview/play.Importación: SRT (timecodes), LRC (synced), Texto plano (duración fija). Preview live de líneas parseadas.
    • Transcripción: faster-whisper (modelo small/medium/large) → segmentos con timestamps → líneas auto-split.Estilos: 10+ presets, animaciones (fade/slide/scale/pop/karaoke/typewriter/blur/bounce), colores, outline, glow, shadow, background, posición, alineación, uppercase.Render ASS: libass via ass_filter → sub.títulos quemados en MP4. Karaoke word-by-word con {\k} tags.

    ⚡ Sistema de Jobs (app/jobs/)

    • Estados: queued → running → cancelling → done/error/cancelled (terminal). Transiciones válidas estrictas.Cancelación Segura: asyncio.Event por job. Runner chequea cancel_event.is_set() en puntos clave. Cancelación → runner limpia → marca cancelled. No puede ser sobrescrito por done.
    • Progreso Real: FFmpeg -progress pipe:1 → parsing out_time_ms → callback async. SSE para frontend.
    • Limpieza: Pruning automático (máx 60 jobs, retiene 50 más recientes).
    • Reintentos: QSV fallback a CPU si falla hardware encoder.

    Pipeline de Render Completo

    PASO 1: SETUP Usuario sube audio + video → Configura fragmento (start/end) → Pulsa "Analizar" PASO 2: ANÁLISIS (Paralelo) AUDIO: librosa → beats, downbeats, secciones, events, envolventes VIDEO: PySceneDetect → escenas + métricas (motion, quality, etc.) → Master normalizado (scale/crop/fps/format fijo, cacheado) PASO 3: PLANIFICACIÓN Para cada estilo solicitado: → Grid de cortes candidatos (beats + midpoints + secciones + events) → Para cada estilo: scoring multi-criterio → selección de escenas → EDL con segmentos (timeline, source, scene, transition, efectos) → Validación EDL (duración, bounds, IDs únicos, min duration) PASO 4: RENDER (Paralelo, máx N paralelo) Para cada EDL: → Render preview (media resolución, ultrafast) → validación → Render final (resolución completa, preset configurado) → validación → Validación ffprobe completa (duración, sync, codecs, keyframes, profile) PASO 5: ENTREGA → MP4s listos para descarga individual o ZIP → MP4s validados, normalizados a −14 LUFS, H.264 High Profile

    Funciones Clave del Editor

    • IDs Estables: Cada segmento tiene id UUID estable. Selección/movimiento/eliminación por ID, no por índice.Duración Derivada (Ripple): Duración EDL = suma de segmentos. Acortar último segmento acorta EDL. Límite de crecimiento = duración del fragmento de audio.
    • Guardado Seguro: Secuencia atómica (seq counter) evita race conditions. beforeunload avisa si hay cambios sin guardar. Badge "render desactualizado" si edited_at > render.created_at.
    • Keyboard-First: Tab navigation, Enter/Delete/Space shortcuts, focus visible, skip links, ARIA labels completos.Render Preview vs Final: Preview = media resolución + ultrafast. Final = resolución completa + preset configurado. Ambos usan MISMO EDL guardado.

# Bandas: kick(40-120), bass(60-250), snare(200-4000), hat(6000-11000)
band_energy = {band: mean(stft[mask]) for band, (low, high) in BANDS.items()}
flux = sqrt(sum(diff(stft, axis=1)**2, axis=0))

    Normalización de Strength (Fix Crítico)

    Bug Original: Normalizaba cada beat individualmente → strength = clamp(_norm([strength]), 0, 1)[0] → siempre 1.0 → downbeats falsos, jerarquía aplastada.
    Fix: Normalización vectorial UNA vez: strengths = _norm(np.array(raw_strengths), 99.0). Preserva jerarquía → downbeats reales detectables.

    Downbeat Confidence

    Algoritmo: 4 fases (0-3) → suma strength por fase → mejor fase = downbeats. Confidence = (best - second) / best * min(1, n_beats/8). Si pocos beats o fases empatadas → confidence baja.

    Sistema de Jobs - Detalle Técnico

    Máquina de Estados

    TERMINAL = {"done", "error", "cancelled"}

# Transiciones válidas:
queued    → running
running   → cancelling (si cancel requested)
cancelling → cancelled (runner confirma)
running   → done (éxito)
running   → error (fallo)
cancelling → NO puede ir a running/queued/done
cancelled → TERMINAL (inmutable)

    Cancelación Segura

    async def cancel(job_id):
    job = await store.get(job_id)
    job["cancel_requested"] = True
    if job["status"] in TERMINAL: return job
    job["status"] = "cancelling"
    event = events[job_id]
    event.set()  # Notifica al runner
    return job

# En runner:
cancel_event = await jobs.event(job_id)
async def on_progress(value):
    if cancel_event.is_set():
        raise ProcessingError("Cancelado", code="cancelled")
    await jobs.update(job_id, progress=value)

    Progreso Real (FFmpeg)

    async def run_ffmpeg(args, duration, on_progress, cancel_event):
    proc = await asyncio.create_subprocess_exec(
        FFMPEG, *args,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )
    while True:
        line = await proc.stderr.readline()
        if not line: break
        line = line.decode().strip()
        if line.startswith("out_time_ms="):
            ms = int(line.split("=")[1])
            progress = min(1.0, ms / 1000 / duration)
            await on_progress(progress)
        if cancel_event.is_set():
            proc.kill()
            raise ProcessingError("Cancelado", code="cancelled")

    SSE para Frontend

    async def stream(job_id):
    last = None
    while True:
        job = await jobs.get(job_id)
        payload = json.dumps(job)
        if payload != last:
            yield f"event: update\ndata: {payload}\n\n"
            last = payload
        if job["status"] in TERMINAL:
            yield f"event: end\ndata: {payload}\n\n"
            break
        await asyncio.sleep(0.5)
